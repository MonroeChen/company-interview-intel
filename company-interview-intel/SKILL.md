# 目标公司面试探查

## Overview

把「公司名（+ 可选岗位 / JD / 个人经历 / 补充材料）」变成两份可直接用于求职面试的 Markdown：

1. **深度探查报告**：先看懂这家公司怎么赚钱、谁在决策、护城河和风险在哪。
2. **对话作战手册**：岗位确定后，把报告压成能上场的话——硬事实、痛点原话、反问、行为题、红旗、速记卡。

质量标准对齐样本《智一科技深度探查报告》与《面试智一科技销售岗-对话作战手册》：先给判断再铺证据；数字带口径；事实 / 推断 / 未核实分层；骨架固定、血肉按这家公司长。

## When to Use

- 用户要做目标公司分析、面试前调研、公司深度探查、面试作战手册
- 用户只给了公司名，或同时给了岗位 / JD
- 用户提到：这家公司是做什么的、怎么准备面试、面试该问什么、竞品是谁

不要用于：尽调估值报告、股权法律意见、非公开数据刺探、编造内部财务或刊例。

## Required Input Contract

执行前只强求公司名。其余缺了就先做阶段 1，不要一次问齐。

| 输入 | 必填 | 说明 |
|---|---|---|
| 公司名称 | 是 | 品牌名亦可。同名公司、集团/子公司、品牌 vs 工商名不清时，**先停下来确认主体** |
| 面试岗位 / JD | 否 | 有则阶段 1 第六章按该业务线加深；无则阶段 1 结束后再问，才进入阶段 2 |
| 个人经历 / 简历 | 否 | 有则手册第 6 节用真实案例改写；无则给岗位通用答法，并标明「用自己的案例替换」 |
| 补充材料 | 否 | 官网、deck、招聘页、年报、聊天记录等，**优先于公开检索** |

## Core Workflow

按顺序执行。每步在报告或手册里留痕（来源、口径、推断线索）。

### Step 0 · 确认主体

- 解析用户给出的名称，检索工商全称、品牌、关联主体。
- 命中多个主体、集团与子公司混淆、或品牌与运营公司分离时：**先问用户再写**，禁止默默选一家。
- 记下将使用的简称（用于文件名）。

### Step 1 · 公开资料探查

按优先级搜集，能交叉验证的必须交叉验证：

1. 用户提供的材料
2. 官网 / 关于我们 / 产品页 / 投资者关系 / 年报公告
3. 官方招聘页（规模、组织、技术栈、岗位真实职责）
4. 权威媒体与行业报道（现场报道优于转载标题）
5. 工商 / 融资数据库
6. 可实测的公开数据（站点、内容矩阵、社媒公开指标等）

检索时用浏览器或公开搜索；读到正文再引用。只看到标题、页面被拦截、OCR 不确定，必须降级并在可信度章写明。

**分层标注（全文强制）**

- **事实**：有出处，写来源与日期
- **推断**：必须写推断线索；面试中不得当事实说
- **未核实 / 冲突**：两说并存，不擅自裁定
- 查不到就写「未核实」，并列进文末清单
- 公司自述 vs 第三方 vs 实测，三套口径不合就拆开写

**红线**：不编造营收、人数、刊例、毛利、股权；宣传口径不升格为已验证；不对齐到不同量级的公司当竞品。

### Step 2 · 写深度探查报告

读取 `references/report-skeleton.md` 与 `references/writing-standards.md`，按固定一级目录成稿。二级及以下按这家公司生长，不要写成百科词条。

**岗位已知时**：第六章对准该岗位所在业务线，写透怎么赚钱、谁买单、怎么交付、和别的线怎么咬合。**仍然不写面试话术。**

**岗位未知时**：第六章选最能解释「这门生意怎么赚钱」的那一条。

**第七章内部身份视角（报告 A）**：第一人称。固定写最高决策者；另写 2～3 个真实关键角色。岗位已知时，必须包含该岗位的上级或对口角色。每人写：核心命题、每天盯什么、不该做什么、怎么被考核、和别人的接口。

### Step 3 · 阶段 1 交付

1. 将完整报告写入工作区：`{公司简称}-深度探查报告.md`
2. 对话摘要只写短的：
   - 一句话定位
   - 3～5 条面试最该记住的点
   - 最大风险
   - 专项补强写了哪条
   - 还缺什么 / 仍未核实
3. 若岗位未给：问清岗位（及可选的个人经历）后再进入阶段 2。不要在阶段 1 输出手册。

### Step 4 · 写对话作战手册

前提：报告 A 已完成，岗位已明确。读取 `references/handbook-skeleton.md` 与 `references/role-playbooks.md`。

- 手册只引用报告里核过的事实；刊例 / 毛利 / 提成 / 人数等内部数字若出现，必须标明行业推断，并指向第 4 节去核实。
- 文首注明岗位类型（五类之一），JD 对不上就选最近一类并声明「实际职责以面试核实为准」。
- **身份视角（手册）**：禁止复制报告 A 的第一人称。用求职者第二人称，把 A 里每个身份压成「他在意什么 / 你该多聊 / 你该少聊」；另写「以本岗位视角读公司」。
- 有个人经历：第 6 节改写成用户的案例。没有：给模板并提示替换。

### Step 5 · 阶段 2 交付

1. 写入工作区：`面试{公司简称}{岗位}-对话作战手册.md`
2. 文首指向同目录探查报告
3. 对话摘要只写短的：战略一句、必问三题、必答三句、最值得警惕的红旗

若用户只要求手册且报告已在本对话或工作区存在，可跳过阶段 1 的重写，但必须先读报告；报告不存在则补做阶段 1。

### Step 6 · 自检（不可跳过）

用 `references/self-checklist.md` 逐项过。未通过必须修订后再交付。

## Dual Identity Rule

两份都写身份视角，职责不同，禁止互相粘贴。

| | 报告 A | 手册 B |
|---|---|---|
| 人称 | 第一人称（我是 CEO / 商务负责人 / …） | 第二人称（你面试时） |
| 目的 | 理解房间里的人怎么想 | 进了这个房间你怎么开口 |
| 内容 | 经营逻辑、KPI、接口 | 他真正在意 → 你该多聊 / 少聊；本岗位在飞轮中的位置 |

## Style & Tone

- 中文正文。判断句要锋利，证据句要克制。
- 表格优先于散文：数字、对照、名单、口径、红旗一律用表。
- 名单按来源拆开（官网客户 ≠ 展商 ≠ 媒体点名），禁止混成一张「客户图谱」冒充已核实。
- 竞品不单独成章，但必须出现：业务或概况里有对照；风险里有竞争；若常被误认为「某集团旗下」则单开澄清节。
- 顾问视角可以给路径建议，但必须标成建议 / 推断，不得伪装成公司已公布战略。

## Resources

执行时按需读取，不要一次性把所有 reference 塞进上下文：

- `references/writing-standards.md` — 事实分层、口径、写作红线
- `references/report-skeleton.md` — 探查报告章节与必写字段
- `references/handbook-skeleton.md` — 作战手册 11 节必写字段
- `references/role-playbooks.md` — 五类岗位的第 1/3/6 节重心
- `references/self-checklist.md` — 出稿前自检

## Iteration Pattern

- 某类公司反复出现的「常见误解」（集团关系、品牌与主体）→ 补进 writing-standards 的澄清节触发条件
- 某类岗位的高频行为题 → 补进 role-playbooks
- 出稿后被用户纠正的口径错误 → 补进 self-checklist
